# 이관 시연 가이드

시연(`DOCS/frontend-design.md` 8.3의 9번)과 리허설에 쓰는 파일과 순서다. 아래 숫자는 로컬에서 실제 user-service·payroll-service에 넣어 확인한 값이다.

## 파일

| 파일 | entity | 내용 | 올렸을 때 |
|---|---|---|---|
| `조직.xlsx` | `HR_ORG` | 회사 1 + 본부 5 + 팀 26 = 32행, 부서유형·부서장 사번까지 채움 | 이슈 없음 |
| `사원.xlsx` | `HR_EMPLOYEE` | 1,252명 (재직 1,199 · 퇴직 53) | 적재 불가 1 · 자동 정리 197 |
| `사원_적재불가0.xlsx` | `HR_EMPLOYEE` | 위와 같고 842행 입사일만 채움. 행 수정 화면이 없을 때 이걸로 | 자동 정리 197 |
| `급여대장_2026-11.xlsx` | `PAY_RESULT_HISTORY`, 시트 `2026-11` | 11월 급여 1,200행. 기본급은 직급·호봉별 표, 계산 칸은 엑셀 수식 | 적재 불가 1 · 확인 필요 10 |

파일을 다시 만들려면 `python -I ../demo.py ~/personas/personas.parquet .` (seed 7, 같은 결과).

## 준비

- **서비스:** user-service·payroll-service(둘 다 이관 내부 API 포함)와 migration-service를 띄운다.
  - migration-service의 `HR_SERVICE_URL`·`PAY_SERVICE_URL`이 두 서비스를 가리켜야 한다.
- **LLM 키:** `GMS_KEY`(개발 서버는 `.env`의 `GMS_API_KEY`)를 넣고 띄우면 고용형태 '정규'·'계약' 8건을 AI가 추천한다.
  - 키가 없어도 허용 값의 줄임말이라 규칙으로 같은 자동 정리 8건이 나온다 (메시지만 'AI 추천' 대신 '줄임말').
- **회사:** user-service에 회사가 정확히 1개 있어야 한다. dev 시드면 이미 있다.
- **직급·직무·직급별 기본급:** 대상에 없어도 된다. 사원·급여 파일에서 뽑아 먼저 넣는다.
- **인증:** 관리자(ADMIN) 토큰이 필요하다.
  - 로컬에서 토큰 없이 해 보려면 migration-service를 `MIGRATION_PERMIT_URLS="/api/v1/admin/migrations/**,/actuator/health,/error"`로 띄운다.

## 순서 (API는 `/api/v1/admin/migrations` 아래)

| # | 화면 동작 | API | 보이는 숫자 |
|---|---|---|---|
| 1 | 이관 작업 만들기 | `POST /` `{"companyId":1,"name":"…","cutoverDate":"2026-12-01"}` | |
| 2 | 조직.xlsx 올리기 → 매핑 확인 → 적재 | `POST /{id}/files` (entity `HR_ORG`) → `PUT /{id}/files/{fileId}/mappings` → `POST /{id}/loads` `{"fileIds":[조직]}` | 이슈 0, 적재 32 |
| 3 | 사원.xlsx 올리기 → 매핑 확인 | `POST /{id}/files` (entity `HR_EMPLOYEE`) → `PUT …/mappings` | 적재 불가 1 · 자동 정리 197 |
| 4 | [자동 정리 197건 적용] | `POST /{id}/fixes` | 자동 정리 0 (적재 불가 1 남음) |
| 5 | 842행 입사일 채우기 | `PATCH /{id}/files/{fileId}/rows/842` `{"values":{"입사일":"2019-03-04"}}` | 적재 불가 0 |
| 6 | 기준정보 확인 (새로 만들 직위·직급·직책·직무) | `GET /{id}/references` | 빈 DB: 새로 47 (직위 5·직급 25·직책 4·직무 13) / dev 시드: 모두 이미 있음 |
| 7 | 미리보기 → 작업명 입력 후 적재 | `POST /{id}/loads?dryRun=true` → `POST /{id}/loads` `{"fileIds":[사원]}` | 묶음 2개: 기준정보 47 → 사원 1,252 |
| 8 | 급여대장 올리기 → 매핑 확인 | `POST /{id}/files` (entity `PAY_RESULT_HISTORY`, sheet `2026-11`) → `PUT …/mappings` | 적재 불가 1 · 확인 필요 10 (아래) |
| 9 | 1113행 사번 오타 고치기 | `PATCH /{id}/files/{fileId}/rows/1113` `{"values":{"사번":"N01162"}}` | 적재 불가 0 |
| 10 | 급여 적재 | `POST /{id}/loads` `{"fileIds":[급여]}` | 묶음 2개: 직급별 기본급 25 → 급여명세서 1,200 |
| 11 | 대사 | `GET /{id}/reconciliation` | 조직 32 · 기준정보 47 · 사원 1,252 · 직급별 기본급 25 · 급여명세서 1,200 모두 ✓ |

- 자동 정리 197건 = 날짜 형식 177 + 고용형태 줄임말 8 ('정규'·'계약') + 휴대폰 앞자리 0 빠짐 12 (`1022710888` → `010-2271-0888`)
- 5번 행 수정 대신 3번에서 `사원_적재불가0.xlsx`를 올려도 된다.
- 급여대장은 사원을 적재한 다음에 넣는다. 직원명부와 사번·퇴사일을 맞춰 보고, 적재할 때 사번으로 user-service 사원 ID를 찾기 때문이다.
- 급여 쪽 확인 필요 10건은 고치지 않아도 적재된다. 급여대장 값 그대로 들어간다 (예: 456행 실지급액은 손으로 적은 3,811,000원).

### 급여대장에서 잡히는 것 (8번)

| 사고 | 이슈 코드 | 행 |
|---|---|---|
| 사번 오타 (숫자 0 대신 영문 O) | `EMP_NOT_IN_ROSTER` (적재 불가) | 1113 |
| 국민연금 요율을 작년 값(4.5%) 그대로 씀 (설정 시트) | `INSURANCE_RATE_OUTDATED` | 시트 전체 |
| 연장수당 수식 배율 1.5가 1.0 | `FORMULA_INCONSISTENT` + `PREMIUM_BELOW_STATUTORY` | 86, 654 |
| 기본급 0 하나 빠짐 | `BELOW_MINIMUM_WAGE` + `PAY_GRADE_BASE_VARIES` | 878 |
| 실지급액을 손으로 덮어씀 | `HARDCODED_VALUE` + `RECALC_MISMATCH` | 456 |
| 3월 퇴사자에게 11월 급여 | `PAID_OUTSIDE_EMPLOYMENT` | 840 |

`GET /{id}/files/{fileId}/formulas`를 열면 엑셀 수식에서 읽은 규칙(예: 연장근로수당 = 통상시급 × 연장근로시간 × 1.5)과 그 규칙에서 벗어난 행이 나온다.

### 급여가 들어가는 모양 (10번)

- 직급별 기본급: 직급마다 가장 많은 기본급 25개 (G1 1호봉 3,500,000원 … 호봉마다 10만원). 878행의 0 빠진 기본급은 들어가지 않는다
- 급여명세서: 1,200명의 2026년 11월. 항목은 기본급·직책수당·식대·연장근로수당·소득세·지방소득세·국민연금·건강보험·장기요양·고용보험, 항목 합 = 지급계·공제계
- 근무일수 등 근태 시간은 0이고 연장 근로시간만 들어간다

## 리허설 · 되돌리기

```bash
cd Backend/migration-service/tools/datagen
python -I demo_run.py --rollback                      # 로컬, 토큰 없이 (MIGRATION_PERMIT_URLS)
python -I demo_run.py --base https://<게이트웨이> --token <관리자 토큰>
```

위 순서를 그대로 돌리고 단계마다 숫자를 찍는다. `--rollback`을 주면 끝나고 되돌린다.

- **되돌리는 순서:** 급여명세서 → 직급별 기본급 → 사원 → 조직 → 기준정보. 뒤 순서가 남아 있으면 앞 묶음은 `LOAD_006`으로 막힌다.
- **같은 작업에 다시 넣을 때:** 적재된 파일은 다시 올릴 수 없다. 새 작업을 만들거나 먼저 되돌린다.
- **되돌리지 않고 새 작업으로 또 넣을 때:** 조직·사원은 같은 부서코드·사번이라 "기존"으로 수정된다. 급여명세서는 같은 사원·같은 달이 이미 있어 실패하니 급여는 먼저 되돌린다.

## 막힐 때

| 증상 | 원인 |
|---|---|
| 화면에서 ④ 미리보기가 안 켜짐 (적재 불가 1) | 842행 입사일 빈 칸. 화면에 행 수정이 없으면 `사원_적재불가0.xlsx`로 올린다 |
| 적재 `LOAD_009` | 호봉 없이 적은 직급이 대상에 호봉별로 여러 개 있음. 시연 파일에서는 생기지 않는다 |
| 적재 `LOAD_007` 인사 서비스 / 급여 서비스 호출 실패 | 그 서비스가 꺼져 있거나 `HR_SERVICE_URL`·`PAY_SERVICE_URL`이 틀림 |
| 적재 실패, 메시지 "부서를 붙일 회사가 N개" | user-service 회사가 1개가 아님 |
| 급여 적재 실패, "사번 …을(를) 인사 서비스에서 찾을 수 없습니다" | 사원을 아직 적재하지 않음 |
| 급여 적재 실패, "급여명세서가 이미 있습니다" | 같은 사원·같은 달 명세서가 payroll에 이미 있음 (이전 리허설을 되돌리지 않음) |
