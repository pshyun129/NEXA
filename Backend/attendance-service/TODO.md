# 근태·급여 남은 작업

> 마지막 업데이트: 2026-11-06

## 1. 다른 팀 관련 (2026-11-06 코드 확인)

- **승인된 휴가 취소** : 지금은 시스템 전체에 경로가 없음. 결재 취소는 진행 중 문서를 결재 전에 기안자가 회수할 때만 되고, 휴가 서비스의 관리자 취소는 결재 철회 클라이언트가 '사용 불가' 구현뿐임. 결재의 최종 처리는 모두 `DocumentCompleter`를 거쳐 결과 이벤트를 발행하므로, 나중에 승인 철회가 생기면 `CANCEL`이 오고 근태는 이미 처리함 (저장한 휴가 삭제 + 다시 판정). 근태 쪽 할 일 없음
- **근무그룹·직위** : 구현한 기준으로만 감. 근무그룹은 근태 `employee_work_group`, 급여명세서는 직급명 표시. user-service에 따로 요청하지 않음
- **명세 문서** : 관리자 근태 현황 `empStatus` 값 `ON_LEAVED` → `ON_LEAVE` 수정 진행 중
- **대체휴일 타입 (휴가 서비스에 전달)** : 근태 holidays API가 승인된 휴일대체 날을 `type: SUBSTITUTE`로 주는데, 휴가 서비스 `HolidayClient.HolidayType`에 없어 상신이 503(LEAVE_015). 휴가 쪽 enum에 `SUBSTITUTE` 추가 필요 (근태는 그대로)
- **휴가 서비스 설정** : 휴가 서비스 자체 결재 결과 반영은 `LEAVE_APPROVAL_RESULTS_ENABLED`, `..._CONTRACT_VERIFIED` 둘 다 켜야 함. 근태는 결재 이벤트를 직접 구독해서 영향 없음
- **휴가 내부 API 노출** : 근태가 부르는 `/api/v1/leaves/internal/requests/{id}/dates`는 Eureka로 직접 호출하므로 게이트웨이에서 외부 노출을 막아도 됨. 근태·급여에는 `/internal` API 없음

## 2. 다른 팀을 기다리는 것

- [ ] **연차수당 (급여, 보류)** : 퇴사한 달 명세서에 남은 연차 × 시급을 지급하는 방식으로 안을 잡아 둠. 지금은 0원
  - 하려면 휴가 서비스에 서비스 간 잔액 조회 API가 필요함 (`/internal/employees/{id}/balances`. 지금 관리자 잔액 API는 '휴가관리자' 직책만 통과해서 명세서를 만드는 인사 관리자는 403)
  - user-service 사원 조회 응답에 `resignDate`도 필요함 (상태만 보고 지급하면 퇴사 후 지난 달 명세서를 만들 때 중복 지급)
  - 재직자 명세서에는 영향 없음. 퇴사자 시나리오가 필요해지면 다시 결정

## 2-1. 나중에 고칠 것 (근태)

- [ ] **근태 신청 상신 중 결재 문서만 남는 경우** (API 명세 정리 중 발견, 드묾)
  - 결재 서비스는 문서를 만들었는데 근태가 응답을 못 받으면(읽기 타임아웃 등) 신청서만 롤백되고 결재함에 문서가 남음. 그 문서를 승인하면 근태가 `신청서 없음`(ATTN_NOT_FOUND)으로 재시도 후 DLT로 보냄
  - 고칠 방법: 결재 호출 실패 시 `GET /api/v1/documents/by-request/{requestKey}`로 만들어진 문서를 찾아 회수, 결과 이벤트에 모르는 신청 ID가 오면 경고 로그만 남기고 무시
  - 연속 상신(더블클릭)은 미리보기의 대기 중 신청 검사로 이미 막혀 있어 `Idempotency-Key`는 두지 않음

## 5. 결정 사항 (2026-11-06)

| 항목 | 결정 |
|---|---|
| 근태 현황 조회 범위 | 팀장·본부장은 자기 부서와 하위 부서, 대표이사와 인사 관리자(role ADMIN)는 전사 |
| 직원 타임라인 조회 | 관리자 + 조회 범위 안의 팀장급. 근무 기록 등록·수정·삭제는 관리자만 |

| 승인된 근태 신청 취소 | 하지 않음. 바꾸려면 근무시간 수정 신청을 새로 냄 |
| 상여금·명절수당 | 분기 마지막 달(3·6·9·12월) 상여금 기본급 100%, 설날·추석 당일이 있는 달 명절수당 기본급 50% |
| 공휴일 등록 | 해마다 마이그레이션 추가 |
| 입사·퇴사 근무그룹 배정 | 별도 배정 없이 기본 근무그룹 자동 적용. 다른 그룹이 필요한 사원만 따로 배정 |
| 휴가 반영 | 결재 결과 이벤트(`LEAVE`)를 받아 휴가 서비스 내부 API로 날짜 조회 후 저장. 승인 여부는 결재 이벤트 기준 |
| 무급휴가 | 시급 × 무급휴가 시간을 지급 항목 "무급휴가 차감"(음수)으로 표시 |
| 급여명세서 직위 칸 | 직급명 표시 (직위 폐지). 컬럼·필드 이름(`position_name`)은 그대로 |
| 엑셀 다운로드 | 하지 않음 (Apache POI로 jar가 커져 CI 아티팩트 업로드 한도 초과) |
| 서비스 간 호출 | `@LoadBalanced` + Eureka 서비스 이름 (compose에 주소 환경변수 두지 않음) |

## 6. 참고

- **로컬 전체 실행** : 루트 `compose.dev.yml` (`docker compose -f compose.dev.yml up -d --build <서비스>`). 서비스 간 호출이 Eureka 이름이라 Eureka도 같이 떠 있어야 함
- **Kafka 수신 실패 처리** : 1초 → 2초 → 4초 재시도 후 `approval.document.result.DLT`(같은 파티션). 시도마다 실패 원인을 경고 로그로 남김
- **결과 이벤트 다시 처리** : 근태를 멈추고 `kafka-consumer-groups.sh --group attendance-service --reset-offsets --to-earliest --topic approval.document.result --execute` 후 다시 시작 (근태 신청·휴가 모두 중복에 안전)
- **급여 기본급** : 운영 마이그레이션 V5 (이미 있는 직급은 유지)
