# 13. 종단(E2E) 시나리오 — 계정·창을 넘나드는 흐름

- 준비: Chrome **프로필 2개**. 이 문서에서 **[L]** = 왼쪽 창(사원/기안자), **[R]** = 오른쪽 창(팀장/관리자). 계정당 탭 하나
- 창 크기: 시연 조건을 재현하려면 1920×1080에서 두 창을 반씩(각 960px) + 브라우저 확대 80%(CSS 약 1,200px). 관리자 단계(빌더·이관)는 [R]을 **최대화 + 확대 100%(Ctrl+0)**
- 각 단계 "기대 결과"는 **L:** / **R:** 로 양쪽 창에서 볼 것을 적었다. 한쪽만 적힌 경우 다른 창은 변화 없음이 정상
- 사전 조건: 00-README D1~D9. 시나리오마다 쓴 신청 #·문서 번호·run #·작업 #를 메모. 같은 날 같은 계정 출근·같은 날짜 신청은 반복 불가 → 계정 로테이션(user3 → user4)

## 알려진 제한(버그 아님)

- 결재자는 근태·휴가 원본과 휴가 날짜, 자동화 원본 이미지를 볼 수 없다(gaps B6·B17·B18).
- 자동화 문서 띠의 워크플로 이름은 ai가 `sourceLabel`을 보내야 보인다(gaps B4).
- 결재함 화면의 목록은 창 포커스 때 다시 읽는다. 탑바 카운터는 60초 주기라 시나리오 중 잠깐 숫자가 어긋날 수 있다(F5로 맞춤).
- 승인 초과는 퇴근 기록이 있는 날만 계산된다(오늘 퇴근 전이면 0).
- 배포 서버는 GPU에 닿는다. 로컬 PC가 GPU 서버에 닿지 않을 때만 E4 실행이 OCR 단계에서 실패하는 것이 정상.
- 설계 8.2의 시연 계정 "user1(사원)·user2(팀장)"는 인사팀에 사원이 1명뿐이라 로테이션이 안 되므로 개발팀 user3·user4 → user5로 바꿔 쓴다(설계 8.2도 2026-11-09에 이 계정으로 갱신). 배포 서버(test1~5)는 계정 구성이 달라 결재자가 다르다.
