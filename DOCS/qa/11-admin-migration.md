# 11. 관리자 데이터 이관 — ①업로드 → ②매핑 → ③검증·자동 정리·행 수정 → ④미리보기 → ⑤적재 → ⑥대사, 되돌리기

- 대상 URL: `/admin/migration`(시작), `/admin/migration/:id`(작업, `?entity=HR_ORG` 또는 `HR_EMPLOYEE`)
- 필요한 계정: admin. **창 너비 1280px 이상**(브라우저 확대 100%)
- 사전 조건: D7. 파일 `조직.xlsx`(HR_ORG 32행), `사원.xlsx`(HR_EMPLOYEE 1,252행, LLM 켜짐 기준 적재 불가 1 · 확인 필요 12 · 자동 정리 185, 적재 불가 1건 = 842행 입사일 비어 있음). 그 밖에 20MB 넘는 파일·`.txt` 파일 1개씩
- **적재하면 실제 user-service DB(부서·사원·기준정보)가 바뀐다.** 테스트 끝에 반드시 **되돌리기(사원 → 조직 → 기준정보)** 로 정리(F절). 적재 상태에서 다른 테스트(조직도·인사·결재선)를 하면 숫자가 달라짐
- 작업 목록이 없으므로 **만든 작업 ID를 메모**

- 작업 목록이 없고 ID로만 연다(gaps B9). 브라우저에 최근 작업을 저장하지도 않는다(설계 문서 2026-11-09 갱신으로 일치).
- 같은 종류 파일을 다시 올리면 이전 파일이 남는다(파일 삭제 API 없음). 화면은 가장 최근 파일만 보여 준다.
- 자동 정리 건수는 서버 숫자를 그대로 쓴다: 데모 파일은 **185건**(설계 문서도 185로 갱신, 2026-11-09). 적용 토스트의 "n칸"은 바뀐 칸 수라 건수와 다를 수 있다.
- 이슈 설명은 서버 메시지 그대로다(한국어 코드 사전 `issueCodes.ts`는 만들지 않음 — 설계 문서 2026-11-09 갱신으로 일치).
- 적재 모달 본문은 영문 종류 코드("HR_ORG 32건")를 보여 준다(설계 6.7 문구 그대로).
- 적재 실패도 HTTP 200 + 묶음 [실패]로 온다(계약). 오류 문구가 JSON째 보일 수 있다(gaps B9·B14).
- 서버 LOAD_006 메시지는 배치 ID 나열이라 읽기 어렵다(화면이 순서를 미리 막아 보통 안 보임).
- 매핑 대상 필드 목록은 서버 스키마를 프론트 상수로 복제한 것이다(메타 API 없음, gaps B9).
- LLM 키가 없으면 ✦AI 추천이 없고 직원구분 8건이 적재 불가로 남는다(gaps B15, 환경 설정).
- 미리보기 통과 상태는 새로고침하면 사라진다(다시 미리보기).
- 1280px 미만에서는 열리지 않는다(설계 8.3 7.5).
