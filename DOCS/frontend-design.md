## 1. 콘셉트

**한 문장**: 처리할 일은 첫 화면에 모두 보이고, Kafka로 늦게 반영되는 결과는 "반영 중"으로 솔직하게 보여 주며, AI가 손댄 곳에는 항상 같은 보라 표식이 붙는 HR 업무 콘솔.

**키워드 3개**
1. **Clear**: 장식 없이 상태 배지, 숫자, 결재선으로 화면을 구성한다. 본문은 14px, 행은 40px로 프로젝터에서도 읽힌다.
2. **Honest async**: 낙관적 UI를 금지한다. 서버에서 확인된 상태만 "승인"으로 표시하고, 그 전에는 "반영 중"으로 둔다. 이 프로젝트의 MSA·Kafka 구조를 UI로 증명하는 장치다.
3. **Visible AI**: AI(OCR 글자 인식, 서류 항목 추출, 자동 검증, LLM 매핑 추천, 이관 값 추천 `ENUM_VALUE_SUGGESTED`, 자동화가 만든 결재 문서)가 관여한 곳에만 Circuit Violet과 `sparkles` 아이콘을 쓴다. 규칙 기반 자동 정리(날짜·숫자 형식)는 AI가 아니므로 보라를 쓰지 않는다. 브랜드 Ledger Blue와 섞지 않는다.

**톤 규칙**
- 문구는 기본적으로 "~합니다"체를 쓴다. 홈 인사, 빈 상태, 완료 카드에만 "~해요"체를 허용한다. 결재·급여·이관 화면에는 감탄 문구를 쓰지 않는다.
- 특정 상용 그룹웨어나 SaaS의 외형과 레이아웃을 복제하지 않는다. AntD 티가 가장 많이 나는 사이드바, 상태 배지, 페이지 헤더는 직접 만든다.

- **팀장(USER 결재자)**: 별도 모드를 두지 않는다. 내 차례가 1건 이상이면 홈 첫 행의 "처리할 일"이 결재를 맨 앞에 보여 준다.
- **탑바(왼쪽 → 오른쪽)**
  - 브레드크럼
  - `ClockChip`: 근무 상태 점 + 출근 시각 + 경과 시간. 누르면 팝오버에 `ableStatusList` 버튼이 나온다. 출근 전에는 칩 자리에 primary 소형 버튼 "출근하기"를 둔다. 퇴근 후 2시간 안이면 "퇴근 취소", 그 이후에는 "수정은 근태 신청 →" 링크를 둔다.
  - 처리할 일 카운터 2개. 0이면 회색 옅은 칩, 1 이상이면 아래처럼 바뀐다(관리 모드에서는 결재 카운터를 끈다).
    - `결재 N`: 1 이상이면 brand 채움
    - `확인 대기 N`: 1 이상이면 warning 채움. 새로 WAITING이 생기면 탭 제목에 `(1) 확인 필요`를 붙인다. 누르면 `/automation`(확인 대기·실행 이력이 있는 업무 자동화 화면)으로 이동한다. 팝오버는 두지 않는다 (2026-11-09 갱신).
    - `반영 중 N` 카운터는 P2(만들지 않는다).
  - 프로필(이름, 부서, 로그아웃)
- **반응형**(style-guide 5.4를 따른다. 2단계로 단순화)
  - 1280px 이상: 사이드바 232, 결재함 2분할 35:65.
  - 1152~1279px: 사이드바 자동 접힘(64), 결재함 2분할 35:65 유지(시연 반창 80%가 여기에 해당).
  - 1024~1151px: 결재함은 목록 + 상세 Drawer.
  - 1024px 미만: "PC(1024px 이상)에서 이용해 주세요" `Result`. 모바일 화면은 P2.
  - 빌더와 이관은 1280px 이상에서만 연다. 데모 8번 전에 오른쪽 창을 최대화하고 확대를 100%(`Ctrl+0`)로 바꾼다(8.3).

- 위 경비 문서(128,000원)와 초과근무는 위임전결상 **팀장 1단계**로 끝난다(1/1). 그래야 팀장 승인 한 번으로 문서가 COMPLETED되어 Kafka 이벤트가 나간다(데모 6·7번). 2단계 결재선(`본부장 🔒필수`)은 100만 원 초과 문서(#0401 서버 증설)에서만 생기고, 이때는 뒤에 required 결재자가 있으므로 [전결]을 노출하지 않는다.
- 탭은 결재 대기·기안함·전체 3개다. 참조·완료 탭은 백엔드 `box`가 생기면 추가한다(P2). 양식 열은 FormType 라벨을 쓰고, ✦자동화·단계 n/m은 결재 대기 탭(상세를 가져온 행)에서만 보여 준다.
- 실행 번호(`run #1287`)는 정수 runId다. 워크플로명은 `GET /runs/{id}` → `GET /workflows/{workflowId}` 2단 조회로 얻고, 실패하면 `run #ID`만 보여 준다.

- **결재선(`ApprovalLine`)**: 가로 스테퍼. 상세, 기안 미리보기, 휴가·근태 신청이 같이 쓴다.
  - 노드 모양: ○ 대기, ● 현재(brand-600 채움 + 2px 링), ✓ 승인(success), ✕ 반려(danger), ⤼ 전결 생략(점선)
  - `required`는 🔒와 "필수" 캡션으로 표시한다.
  - AGREEMENT는 결재 노드와 같은 줄에 step 순서대로 둔다(병렬 레일 없음) (2026-11-09 갱신).
  - 참조와 열람은 점선 뒤에 ◇로 분리한다.
- **현재 차례**: APPROVER/AGREEMENT 가운데 PENDING인 줄의 최소 step이다.
- **버튼**: `useDocumentPermissions(doc, me)` 한 곳에서 계산한다(요구사항 3.4 표 그대로). 내 차례가 아니면 액션 바 자리에 "현재 결재자: 최OO 본부장 · 대기 중"을 표시한다. 버튼을 이유 없이 숨기거나 disabled로 남기지 않는다.
- **승인**: 모달 없이 즉시 처리한다.
- **반려**: `R`을 누르면 액션 바 위로 인라인 textarea가 펼쳐진다(1~1000자, 카운터). `Ctrl+Enter`(mac은 `⌘+Enter`)로 제출하고 `Esc`로 닫는다.
- **전결**: `F`를 누르면 확인 모달이 열린다. 본문은 "이후 결재자 n명(이름 직책)의 결재가 생략됩니다"이고 기본 포커스는 [취소]다. 전결은 뒤에 required 결재자가 없을 때만 노출된다(요구사항 3.4).
- **처리 후**: 다음 문서로 자동 이동하고 토스트 "#0409 승인 완료"를 띄운다. 출처가 있는 문서(근태·휴가)이면 "원본 반영은 몇 초 걸릴 수 있습니다"를 덧붙인다.
- **재기안**: 출처 문서는 재기안 대신 "원래 화면에서 새로 신청 →" 링크를 보여 준다.

- **P1**이고 시연 동선에 없다. 블로커(요구사항 6장 #2~#4)가 풀려도 데모 슬롯은 추가하지 않고 Q&A용으로만 쓴다. 휴가 제출을 붙일지는 **3주차 말**에 판단한다.
- 과거 날짜와 같은 날짜 중복 선택만 클라이언트에서 막는다. 주말·기신청·반차 조합은 preview `reasons[]`로 보여 준다(요구사항 3.5). 공휴일은 `/attn/holidays`로 표시한다.
- 선택이 바뀌면 300ms 디바운스 후 preview를 호출한다. `reasons[]`는 해당 날짜 행 바로 아래와 캘린더 셀의 `!` 마커 두 곳에 함께 표시한다.
- `UNVERIFIABLE`이면 warning 배너 "공휴일 확인에 실패했습니다. 잠시 후 다시 확인해 주세요"와 [다시 확인]을 띄운다.
- `Idempotency-Key`는 화면에 들어올 때 `uuid` v4로 만든다(`useIdempotencyKey`).
  - 201: 토스트 "휴가를 신청했습니다"를 띄우고 신청 상세 Drawer(`/leave/requests/:id`, 결재 문서 번호·상태·[결재 문서 보기]·[회수])로 이동한다 (2026-11-09 갱신).
  - **202 SUBMITTING**: 화면을 닫지 않는다. warning 채움 배지 "처리 확인 중"과 [같은 요청으로 다시 확인]을 띄우고 같은 키를 쓴다.
  - 200: 기존 결과를 그대로 보여 준다.
- `LEAVE_010`이면 info 배너 "휴가 정책이 배정되지 않았습니다. 인사 담당자에게 문의해 주세요"를 띄운다. 데이터가 없는 것과 구분하기 위해서다.
- **백엔드 갭(요구사항 6장 #2~#4)**: #1(CORS)은 같은 origin 프록시로 해소됐다. preview는 **실제 API**로 호출하고 UNVERIFIABLE 배너로 정직하게 보여 준다. 제출만 `FeatureGate("leaveSubmit")`로 감싸 버튼 자리에 "제출 연동 대기(공휴일 경로·결재 연동)" info 안내를 둔다. MSW는 쓰지 않는다.

- 노드 제목, 팔레트 그룹, 분기 라벨은 카탈로그(`/nodes/categories`, `/nodes/{type}`)의 `name`·`category`·`branches`를 그대로 쓴다. 팔레트 그룹은 서버 카테고리 5종(입력, AI, 규칙·분기, 사람 확인, 문서·알림)이다.

  - 서버 validate: `issues[].nodeId/edgeId`에 danger 2px 테두리를 단다. 서버는 순서를 검사하지 않는다.

- 저장은 **[저장] 버튼(`Ctrl+S`)** 이다. 자동 저장은 P2. 변경이 있으면 "저장 안 됨" 인라인 표시와 이탈 경고(`useUnsavedGuard`)를 둔다.
- 입력 폼·노출 화면·버전 롤백·복제 UI는 P2다. 배포 버튼은 P1(확인 모달).
- **예외: 노출 화면 중 HOME 토글만 P1로 구현**(2026-11-09, `9ca428b`). 사원 목록(`GET /workflows/available?screen=HOME`)은 배포 버전 + `placements`에 HOME이 있어야 보이는데, 새 워크플로는 `placements=[]`라 관리자가 빌더에서 만들고 배포해도 사원에게 보이지 않았다(시드 스크립트로는 새 워크플로를 덮을 수 없음). 헤더 [배포] 옆 스위치로 `PUT /workflows/{id}/placements`를 호출하고, HOME 외 화면 코드는 그대로 둔다. 노출이 꺼져 있으면 배포 확인 창에 알린다. 화면 코드 여러 개를 고르는 [노출 화면] 탭은 여전히 P2.

- **역할 검사 부재(요구사항 6장 #14)**: 메뉴는 ADMIN 전용으로 둔다. 발표 자료에 "FastAPI 빌더 라우터에 ADMIN 의존성 추가 예정(백엔드 작업)"을 명시한다. 메뉴를 숨긴 것만으로 해결됐다고 말하지 않는다.

- 숫자는 심각도별 **이슈 건수**(`issueTotals`)다. 행 수가 아니므로 "정상 N행" 구간은 그리지 않고, 행 수는 "1,252행" 텍스트로만 보여 준다. 카운트다운 연출은 `FixApplyResponse.issueTotals` 변화값으로 한다.
- 자동 정리(FIX) 묶음은 규칙 기반이라 info 톤 + `wand` 아이콘이다. AI 표식(✦ AI 추천)은 이슈 코드 `ENUM_VALUE_SUGGESTED` 묶음과 매핑 단계 `suggestedBy=LLM`(reason 툴팁)에만 단다.
- 대상 필드 드롭다운은 `EntitySchemas.java`에서 옮긴 HR_ORG·HR_EMPLOYEE 하드코딩 상수를 쓴다. 이슈 설명은 서버 메시지를 그대로 쓴다(`issueCodes.ts` 없음) (2026-11-09 갱신).
- 적재 모달은 본문에 숫자를 적는다("HR_EMPLOYEE 1,252건이 실제 DB에 적재됩니다"). 작업명을 그대로 입력해야 [적재] 버튼이 활성화된다. 되돌리기(P1)는 LOADED 배치 중 뒤 순서(사원 → 조직 → 기준정보)에 LOADED가 남지 않은 배치에만 둔다. 막힌 행에는 "사원 → 조직 먼저 되돌려야 합니다"를 보여 주고, 확인 창은 작업명 입력이 필요하다(서버 LOAD_005·LOAD_006) (2026-11-09 갱신).
- 대사 화면은 entity별 행으로 "원본 32 = 적재 32 ✓", "원본 1,252 = 적재 1,252 ✓"를 보여 준다(`ReconciliationItem`의 source/loaded/match).
- 행 단위 PATCH 인라인 편집은 P1이다. 시연 파일은 BLOCK을 0~1건으로 맞춘다(요구사항 8장 #11). LLM 규칙 요약·수식 카드는 P2.
- **행 단위 표만 서버 페이징**이다(`useServerTable`). 나머지 표는 모두 `useClientTable`을 쓴다.
- **작업 목록 API 없음(요구사항 6장 #13)**: 시작 화면에 [새 작업]과 [작업 ID로 열기] 입력만 둔다. localStorage 최근 작업 목록은 만들지 않았다(목록 API는 develop 미머지 브랜치에만 있음) (2026-11-09 갱신). 원본 행 조회 API가 없으므로 행 편집은 issues `content`에 온 필드만 다룬다.

### 7.3 비동기 정책 (하나로 고정)

| 대상 | 트리거 | 표시와 폴링 |
|---|---|---|
| `AsyncSync` | Kafka 전파가 필요한 경우만: 휴가 회수(결재 문서 회수), 결재함에서 출처 문서(근태·휴가)를 승인·반려한 직후 그 출처 신청. **근태 신청 회수는 동기 처리라 대상이 아니다**(응답으로 즉시 갱신) | info 칩 "반영 중 · 5초 전 확인". 5초 간격 + 창 포커스 재조회. 반영되면 최종 배지로 바뀌고(200ms) 토스트를 띄운다. 2분이 지나도 그대로면 폴링을 멈추고 neutral "반영 지연 · 결재 문서에서 확인 ↗". 탑바 "반영 중 N"과 "승인됨 · 근태 반영 중" 중간 상태는 두지 않는다(반영이 1~3초라 거의 관측되지 않고, 목록에 `approvalDocId`가 없어 행마다 상세 조회가 필요하다) |
| 진행 중 신청 목록 | PENDING, SUBMITTED, SUBMITTING 행이 화면에 보일 때 | 5초 간격 + 포커스 재조회, 2분 뒤 중단. 완료된 행은 `completedAt`을 "근태 반영 HH:mm:ss"로 표시한다(시그니처 2의 증거) |
| `RunMonitor` | 실행 화면 | QUEUED·RUNNING 1.5초, WAITING 10초, 종료 상태와 숨겨진 탭(`document.hidden`)에서는 중단, resume 후 1.5초로 재개 |
| 전역 카운트 | 탑바, 사이드바 배지 | 60초 + 포커스, 숨겨진 탭과 관리 모드에서는 중단 |
| `useDocuments` / `usePendingDocuments` | 결재 대기 탭, 홈 위젯 | 백엔드 `box=PENDING`·`DRAFTED` 사용(`useApprovalBox`·상세 일괄 조회·"계산 중 n/m" 없음). 목록은 창 포커스 때 다시 읽고, 탑바 카운터(`/documents/count`)는 60초마다 읽는다. 처리 후 상세·목록을 invalidate (2026-11-09 갱신) |

낙관적 UI는 금지한다. 결재 처리 직후 원 신청을 "승인"으로 미리 바꾸지 않는다.

## 8. 시연 시그니처 경험과 데모 시나리오

### 8.1 시그니처 3개
1. **Live Run Theater**: 영수증 한 장을 올리면 노드가 차례로 켜지고 소요 시간이 찍힌다. 자동 검증이 GMS 교차 추출과 금액이 다르다고 판단해 '사람 확인' 분기로 멈추면, 불일치 1칸만 강조된 HITL이 뜬다. 고쳐서 계속하면 결재 문서가 생성된다. 메시지는 "AI가 다 하지 않는다. 확신이 없는 칸만 사람에게 묻는다"이다.
2. **두 창으로 보여 주는 Kafka**: 팀장 창에서 승인하면(토스트에 승인 시각) 사원 창의 신청 행이 손대지 않아도 "결재 대기"에서 "승인 · 근태 반영 10:21:04"로 바뀐다. approval 아웃박스가 1초 간격으로 발행하므로 반영은 대개 수 초 안에 끝난다. 중간 상태를 연출하지 않고, **두 서비스가 각자 기록한 시각**으로 비동기 반영을 증명한다.
3. **빨간 숫자가 0이 되는 순간**: 이관 화면에서 [자동 정리 185건 적용]을 누르면 이슈 막대가 줄고 숫자가 0까지 카운트다운된다. 남은 BLOCK 1건을 고치고(행 수정이 P1에서 빠지면 BLOCK 0건 파일 사용) 적재한 뒤 대사 화면 "원본 1,252 = 적재 1,252 ✓"로 마무리한다.

### 8.2 무대 구성
- 1920×1080 프로젝터에 Chrome 창 두 개를 반씩 나란히 띄운다(각 960px, 브라우저 확대 80% → CSS 폭 약 1,183~1,200px, style-guide 5.4의 1152~1279 구간). 왼쪽은 **사원(개발팀 user3, 다음 계정 user4)**, 오른쪽은 **팀장(개발팀 부서장 user5)**이다. 개발팀 위로 기술본부(user8) → 회사(user9) (2026-11-09 갱신).

### 8.4 실패 대비
- 시연용 영수증 2장: A는 OCR 신뢰도는 기준 이상이고 GMS와 금액만 다른 영수증('사람 확인' 분기), B는 자동 확정. 두 LLM 결과가 달라야 하므로 리허설마다 A의 경로를 확인한다. 흔들리면 시연 워크플로의 자동 검증 `min_confidence`를 0.99로 올려 항상 '사람 확인'으로 보낸다(이때 교차 추출 열이 없는 2열 HITL로 진행).
- FAILED이면 깔끔한 실패 화면과 [다시 실행]을 보여 준다.
- 7번 반영이 2분 안에 일어나지 않으면 "반영 지연"으로 바뀌는 것 자체를 정직한 UX로 설명한다. Kafka 브로커 + attendance 리스너 E2E는 4주차 말 점검 항목이다.
- 1·2번은 하루 1회 출근 제약 때문에 같은 계정으로 반복할 수 없다. 리허설마다 계정 로테이션표(요구사항 8장 #4)를 쓴다.
- 전체 흐름을 녹화한 백업 영상을 준비한다(LLM·OCR 장애 시 3·4번을 영상으로 대체).

### 8.5 Q&A 대비 문장
- "결재함은 백엔드 box API가 없어 N+1로 계산하고, 진행률로 숨기지 않고 보여 줍니다. box가 추가되면 훅 하나만 바꿉니다."
- "빌더 API와 실행 조회 API에는 아직 역할·소유자 검사가 없습니다. 메뉴는 ADMIN 전용이고, FastAPI에 의존성을 추가하는 백엔드 보완을 예정하고 있습니다."
- "원본 이미지는 다운로드 API가 생기기 전까지 업로드한 브라우저에서만 보입니다."
- "자동 정리는 대부분 규칙 기반이라 AI 표식을 달지 않았고, AI가 값을 추천한 묶음에만 표식을 달았습니다."
