### 반응형 구간(코드 `shell/useViewport.ts`)

| 창 너비(CSS px) | 구간 | 화면 차이 |
|---|---|---|
| ≥ 1280 | wide | 사이드바 펼침(232px, [접기] 버튼 있음). 결재함 2분할. **빌더·이관 열림** |
| 1152 ~ 1279 | demo | 사이드바 자동 접힘(아이콘만, 마우스 올리면 툴팁 라벨), [접기] 버튼 없음. 결재함 2분할. 빌더·이관은 "1280px 이상 화면에서 열립니다" |
| 1024 ~ 1151 | compact | 사이드바 자동 접힘. **결재함 상세가 오른쪽 Drawer(70%)** 로 열림. 빌더·이관 열리지 않음 |
| < 1024 | narrow | 화면 전체가 "PC(1024px 이상)에서 이용해 주세요." 한 줄 |

창 너비 조절: Chrome DevTools(F12) → Toggle device toolbar(Ctrl+Shift+M) → Responsive에서 너비 입력, 또는 브라우저 확대/축소(Ctrl+ +/-)로 CSS 너비를 바꾼다(100%에서 1920px 모니터 = 1920).

## 5. 공통 규칙 (모든 파일에 적용)

- **토스트**: 화면 오른쪽 아래, 최대 3개. 성공·정보는 5초 뒤 자동으로 닫힘. **오류 토스트는 자동으로 닫히지 않음**. 오류 토스트 본문 = 서버 메시지 + 줄바꿈 + `오류코드 · Request-Id`. 404는 메시지가 "없거나 볼 권한이 없습니다."로 통일.
- **ErrorPanel(화면 안 오류)**: 빨간 아이콘 + 제목(기본 "불러오지 못했습니다") + 메시지 + 오류 코드(mono) + Request-Id(mono) + [복사](누르면 토스트 "Request-Id를 복사했습니다") + [다시 시도]. 서버 연결 실패면 "서버에 연결하지 못했습니다. 잠시 후 다시 시도해 주세요." 와 코드 `NETWORK`.
- **로딩**: 전체 화면 스피너 없음. 회색 정적 Skeleton(애니메이션 없음).
- **자동 재시도**: 조회(GET)는 502/504/네트워크 오류일 때만 1회 자동 재시도 후 오류 표시. 4xx는 바로 표시. 저장·처리(POST 등)는 재시도 없음.
- **재조회 시**: 이전 데이터를 유지한 채 갱신(깜빡임 없이 바뀌어야 함). 창에 다시 포커스가 오면 오래된(30초 이상) 데이터를 다시 불러온다.
- **상태 배지**: 색 + 아이콘 + 글자를 같이 쓴다. 모르는 값은 회색 배지 + 원문 코드.
- **단축키**: 입력창(input·textarea·select·콤보박스)에 포커스가 있거나 모달 안이면 한 글자 단축키(J/K/A/R/F/`/`/`?`)는 동작하지 않는다. Ctrl(⌘)·Alt를 같이 누르면 한 글자 단축키 무시. Mac이면 표기가 `⌘`, Windows는 `Ctrl`.
- **확인 모달(ConfirmAction)**: 동사형 제목, 기본 포커스는 **[취소]**(모달이 뜨자마자 Enter를 누르면 취소됨), 파괴적 작업은 빨간 확정 버튼, 처리 중에는 바깥 클릭·[취소]로 닫히지 않음.
- **Drawer 닫기**: 오른쪽 위 X, 바깥(마스크) 클릭, Esc 모두 닫힘(AntD 기본). URL이 바뀌는 Drawer(결재·근태 신청·휴가 상세·급여 명세서)는 닫으면 URL에서 id가 빠져야 한다.

## 7. 결과 기록 방법

- 각 표의 마지막 칸 `결과`에 `✅`(통과) / `❌`(실패) / `⏭`(건너뜀, 사유) 를 적고, 필요하면 짧은 메모를 붙인다.
- **❌ 이면 반드시**: ① 재현 단계(표의 단계와 다르면 그 차이) ② 실제 화면(스크린샷 파일명) ③ 오류 토스트/패널의 **오류 코드와 Request-Id**(복사 버튼) ④ 계정·시각·창 너비 를 메모에 남긴다.
- **(확인 필요)** 항목은 통과/실패 대신 실제 동작을 적는다.
- 각 파일 끝 **"알려진 제한(버그 아님)"** 에 있는 증상은 버그로 올리지 않는다. 그와 비슷하지만 다른 증상이면 차이를 적어 올린다.
- 테스트로 만든 데이터(문서 번호, 신청 #, 실행 run #, 이관 작업 #)는 파일 맨 아래 "남긴 데이터" 메모에 적는다(다음 테스트 계정 로테이션에 필요).
- 같은 날 같은 계정으로 다시 할 수 없는 동작이 있다: **출근은 하루 1회**, 같은 날짜 근태/휴가 중복 신청 불가. 계정 로테이션(user3 → user4) 또는 다른 날짜를 쓴다.

## 8. 전체 공통 알려진 제한(버그 아님)

| 증상 | 이유(근거) |
|---|---|
| 결재자(팀장)가 근태·휴가 원본 신청을 열 수 없음(결재 상세에 [원본 신청 보기]가 기안자에게만 보임) | 근태·휴가 상세 API가 본인용뿐(gaps B6·B18) |
| 휴가 결재 문서에 날짜가 없음(제목 "휴가 신청" 고정, 속성 "휴가 일수 n일"만) | gaps B18 |
| 자동화 실행 원본 이미지를 결재자·관리자는 볼 수 없음("원본은 실행한 사람만 볼 수 있습니다") | 다운로드 API가 업로더·요청자만 허용(gaps B17) |
| 홈·업무 자동화의 확인 대기 항목이 "run #ID · 워크플로 #ID"로만 보이고 사유가 없음 | 목록 응답에 이름·사유 없음(gaps B5·B11) |
| 확인 대기 카운터에 관리자의 **테스트 실행**도 섞여 셀 수 있음 | 서버 목록이 테스트 실행을 구분하지 않음(gaps B11) |
| 자동화 실행 화면이 노드 캔버스가 아니라 세로 단계 목록 | 실행 그래프가 응답에 없음(gaps B11, 4주차 결정) |
