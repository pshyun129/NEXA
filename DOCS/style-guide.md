# NEXA 확정 스타일 가이드 v1.0: "Honest Console"

> 기준일은 2026-11-04이다. 이 문서는 `DOCS/frontend-design.md`(이하 "설계")보다 세밀한 **시각·표현 규칙의 단일 기준**이다. 설계와 다르면 이 문서를 따른다.
> 뼈대는 심사 합계 1위인 안 1(refined-enterprise, 17.1점)이다. 안 2의 역할 분리와 AI 출처 언어, 안 3의 토큰 계층·대비 행렬·lint를 붙였다. 두 심사가 지적한 mustAvoid는 모두 뺐고 factErrors는 모두 바로잡았다(14장).
> 이 문서의 대비값과 OKLCH 값은 모두 `node`로 다시 계산했다(WCAG 2.x 상대휘도 공식, OKLab 변환). APCA 값은 싣지 않는다.
> 모든 항목은 하나로 정했다. 설계를 바꾼 항목에는 **[변경]**, 새로 정한 규칙에는 **[추가]**를 붙였다. 이전값, 새값, 근거는 13장에 모았다.
> 상용 서비스(Linear, Toss, Carbon 등)에서는 원칙만 가져오고 외형은 가져오지 않는다.

## 1. 원칙

### P1. 할 일이 먼저 보인다
| 이렇게 한다 | 이렇게 하지 않는다 |
|---|---|
| 홈 첫 행에 "처리할 일"을 전폭으로 둔다 | 환영 배너, 일러스트, 뉴스 카드를 둔다 |
| 화면·카드·모달마다 primary 채움 버튼은 **1개**다. 결재 액션 바에서는 [승인 A]가 그 버튼이다 | [승인]·[반려]·[전결]을 모두 파란 채움 버튼으로 만든다 |

### P2. 확인된 것만 확정으로 보인다
| 이렇게 한다 | 이렇게 하지 않는다 |
|---|---|
| 서버가 확인하기 전에는 info 옅은 배지 "반영 중 · 3초 전 확인"을 둔다 | 낙관적 UI로 미리 "승인"을 띄운다 |
| 서버가 RUNNING을 주면 "실행 중 · 경과 3.2s"를 보여 준다 | 가짜 타자 효과, 점멸 커서, shimmer 텍스트로 "생각 중"을 연출한다 |

### P3. 색의 역할은 셋으로 나뉜다
**보라는 "누가 했나", 노랑은 "당신이 봐야 한다", 파랑은 "당신이 할 일"이다.** 자세한 규칙은 9.1에 있다.
| 이렇게 한다 | 이렇게 하지 않는다 |
|---|---|
| AI가 만든 값에 보라 표식을 단다. 사람이 확인할 칸은 warning, 승인 버튼은 brand다 | 보라를 버튼·링크·CTA에 쓴다. 확인이 필요한 칸을 보라로 강조한다 |

### P4. 색 하나로 말하지 않는다
| 이렇게 한다 | 이렇게 하지 않는다 |
|---|---|
| 상태는 색 + 아이콘 + 텍스트로 표시한다. AI 표면은 1px 테두리 + sparkles + 동사형 라벨을 함께 쓴다 | 배경 틴트만으로 선택이나 AI를 구분한다(brand-50과 ai-50은 ΔE_OK 0.012로 사실상 같은 색) |

### P5. 평면, 불투명, 3m 가독성
| 이렇게 한다 | 이렇게 하지 않는다 |
|---|---|
| 카드는 1px n-200 보더로만 구분한다. 그림자는 sticky·pop·modal에만 쓴다 | 카드 그림자, 카드 안 카드, 표 세로선, `backdrop-filter`, 반투명 면을 쓴다 |
| 정보 텍스트는 13px 이상으로 쓰고, 모든 fg/bg 조합의 계산값을 표로 관리한다 | 흐림 효과에 opacity를 쓴다. 연회색 placeholder를 쓴다 |

### 그라디언트 없이 "요즘 제품" 인상을 만드는 6가지 (발표 서사)
1. 정밀한 1px 보더
2. 표·KPI·시각의 tabular 숫자 정렬(`.nx-num`)
3. 키보드 힌트 `Kbd` 칩
4. 실행 중 노드의 실시간 경과 카운터와 실행 기록 타임라인
5. 서버가 준 사유를 그대로 보여 주는 AI 확인 화면("확인이 필요한 이유")
6. 120~200ms의 기능적 전환(배지 교체, 결과 카드 등장)

## 3. 색

### 3.1 토큰 계층
```
primitive  color.brand.600, color.n.500, color.ai.700 ...           원시 hex, 의미 없음
   ↓ 참조
semantic   text.default → n.700 / status.success.fg → #1A7540 ...    의미
   ↓ 참조
component  table.header.bg → n.50 / button.default.border → n.300  컴포넌트
```
- 화면 코드는 semantic과 component 토큰(`--nx-text`, `--nx-border-input` 등)만 쓴다. primitive 직접 참조와 hex 리터럴은 `src/styles/`, `src/status/statusMap.ts` 밖에서 쓰지 않는다(코드 리뷰 체크 항목, lint는 두지 않는다).
- 런타임 값은 hex다. OKLCH는 참고값이다.

### 4.4 한글 줄바꿈
```css
body { word-break: keep-all; overflow-wrap: break-word; line-break: strict; }
.nx-break-any { overflow-wrap: anywhere; }   /* 이메일·URL·파일명 셀에만 */
h1, h2, h3, .nx-balance { text-wrap: balance; }
```
- `overflow-wrap: anywhere`는 전역에 걸지 않는다. 걸면 표와 flex의 min-content가 무너진다.
- 표 셀은 1줄 말줄임(`ellipsis`)이고, 잘린 셀에는 `title` 툴팁을 단다. 예외로 제목·사유·오류 열은 2줄까지 보이고 그 뒤를 말줄임한다. 제목 열 최소 폭은 200px이다.
- 숫자, 금액, ID는 줄바꿈하지 않는다(`white-space: nowrap`).
- 문단 최대 폭은 640px(약 72자)다. 대상은 모달 본문과 배너 설명이다.
- `text-wrap: pretty`는 쓰지 않는다.

| 날짜(표, 올해) **[변경]** | `MM.DD(요일)`. 다른 해는 `YYYY.MM.DD` | `11.04(수)`. 하이픈 표기는 원본 추출값을 그대로 보여 줄 때만 쓴다 |
| 시각 | 24시간 `HH:mm`. 초는 실행 기록에만 | `08:52`, `10:11:02` |
| 일시 | `YYYY.MM.DD HH:mm`(표 올해는 `MM.DD HH:mm`) | `2026.11.04 10:12` |
| 범위(날짜·시각 공통) | 물결표 앞뒤 공백 | `11.10(월) ~ 11.12(수)`, `08:52 ~ 18:10` |
| 상대 시각 | 1분 미만 `방금`, 60분 미만 `n분 전`, 이후는 일시. AsyncSync는 `n초 전 확인` | `15초 전 확인` |
| 건수·인원 | 쉼표 + 단위 붙임 | `1,252행`, `12건`, `3명` |
| 신뢰도 | 서버 `reasons` 문자열을 그대로 쓴다(기준값은 응답에 없다). %로 바꾸지 않음 | `OCR 신뢰도 낮음: 0.71` |
| 진행 | `n/m` | `계산 중 12/30` |
| 빈 값 | em dash, n-500 | `—` |

모든 포맷 함수는 `src/format/`(`Intl.NumberFormat('ko-KR')`, dayjs `Asia/Seoul`)에만 둔다. 화면에서 `toLocaleString`을 직접 부르지 않는다.

### 9.3 근거 진입점
AI 근거 Popover는 두지 않는다(응답에 필드별 근거·기준값이 없다). 근거는 두 곳에서만 보여 준다.
- HITL 상단 "확인이 필요한 이유": 서버 `reasons` 문자열을 원문 그대로 목록으로 둔다(warning 블록).
- 결재 문서 `AiBand`의 [원본 실행 보기 ↗] → RunMonitor(실행 기록 타임라인).

AiMark에는 `aria-label="AI가 생성한 값: AI 추출"`을 단다.

### 9.4 출처 상태 3종 (HITL 필드, 이관 매핑 공통)
| 상태 | 시각 | 행동 |
|---|---|---|
| 확인 필요 | warning-bg 행 + 왼쪽 inset 3px warning-fg + `triangle-alert` 16 + "불일치". 행 안 보조 텍스트는 n-600 | 추출값 셀을 클릭하면 확정값으로 복사(hover n-50, cursor copy) |
| 자동 확정 | 글자 n-500, `check` success-fg + "자동 확정". 접지 않는다 | 수정 가능 |
| 직접 수정 | `pencil` 12 + "직접 수정" caption n-600 | 되돌리려면 추출값 셀을 다시 클릭(복사)한다. 별도 [AI 값으로 되돌리기]는 두지 않는다 |

- 불일치 행을 맨 위로 정렬하고, Tab은 다음 확인 필요 행으로 이동한다.
- 요약: 표 아래에 `불일치 1 · 일치 2`를, 제출 버튼 왼쪽에 `직접 수정 1개`(small `.nx-num`)를 둔다.
- `gms_fields`가 null이면 교차 추출 열을 숨기고 "AI 추출 | 확정값" 2열로 그린다. 이때 ⚠는 서버 `reasons`·`problems`의 필드명으로만 단다.
- 주 버튼 [확인하고 계속 Ctrl+Enter]는 brand primary다.

### 9.5 신뢰도 표기
1. 단독 숫자 배지와 `%` 게이지·막대·그라데이션은 쓰지 않는다.
2. 신뢰도는 서버 `reasons` 문자열(예: `OCR 신뢰도 낮음: 0.71`)로만 보여 준다. 기준값은 응답에 없으므로 `값 / 기준` 형식을 만들지 않는다(백엔드가 구조화된 reasons를 주면 그때 정한다).
3. 필드 행에는 상태(⚠/✓/✎)만 둔다.
4. 이관 LLM 매핑 `reason`은 서버 문자열 앞에 "AI 근거:"를 붙여 툴팁으로 보여 준다.

### 9.6 실행 중 상태
- 서버가 준 상태(QUEUED, RUNNING, WAITING, 종료)만 표시한다. "생각 중" 같은 상태는 만들지 않는다.
- 실행을 시작하면 초안 그래프(`GET /workflows/{id}`)의 모든 노드를 QUEUED(점선)로 먼저 그린다. 이것이 실행 계획 역할을 한다.
- RUNNING에는 경과 칩을 둔다.
- 캔버스 아래에 실행 기록 타임라인(8.12)을 둔다. 폴링은 1.5초를 유지하되 텍스트는 상태가 바뀔 때만 다시 그린다.
- 금지: 타자 효과, 점멸 커서, shimmer, 그라디언트 진행 막대, 글로우, 의인화 문구.

### 9.7 확인 강도 3단계
| 단계 | 언제 | 형태 | 예 |
|---|---|---|---|
| L0 사후 보고 | 되돌릴 수 있고 영향이 작음 | 인라인 "저장됨 14:21", 성공 토스트 | 승인, 반려, 저장, 자동 확정 |
| L1 실행 전 영향 표시 | 다른 사람이나 여러 건에 영향 | 확인 모달 본문에 숫자 | 전결("이후 결재자 n명 생략"), 자동 정리("이슈 210건 · 필드 2종 변경"), 배포, 회수 |

### 9.8 출처 표시
- 형식: `출처: 영수증_1104.jpg · OCR 글자 인식 · run #1287 · 2026.11.04 10:11`. small 13 n-500이고 파일명과 run은 mono다.

## 10. 보이스&톤

### 10.1 문체
| 상황 | 문체 | 예 |
|---|---|---|
| 기본(안내, 오류, 모달, 배너) | ~합니다 | "공휴일 정보를 불러오지 못했습니다." |
| 홈 인사, 빈 상태, 완료 카드 | ~해요 허용 | "처리할 결재가 없어요" |
| 결재, 급여, 이관 | ~합니다만. 감탄 문구와 이모지 금지 | |
| 상태 라벨, 토스트 제목 | 명사형 | "승인 완료", "반영 중" |

- 능동형으로 짧게 쓴다: "~했습니다", "~하지 못했습니다".
- 존칭 과잉("~하시겠습니까?", "고객님")은 피한다. 확인은 평서문 제목과 동사 버튼으로 대신한다.
- 고정 용어: 사원, 결재·승인·반려·회수·전결, 기안·상신, 근태 신청, 자동화, 실행, 확인 대기, 직접 수정.

### 10.2 AI 문구
- 주어는 "AI", "자동화", 단계명이다. 1인칭("제가", "저는")과 의인화("AI가 열심히 일하고 있어요")는 쓰지 않는다.
- 확신을 과장하는 말("정확한", "완벽한")은 쓰지 않는다.
- 판정 어휘는 "확인 필요", "자동 확정", "직접 수정" 셋으로 고정한다. 노드·분기 이름은 서버 카탈로그 문자열을 그대로 쓴다.

### 10.3 버튼 라벨
- 동사 또는 "목적어 + 동사"로 2~8자다: `승인`, `반려`, `휴가 신청`, `확인하고 계속`, `반려하고 종료`, `배치 되돌리기`, `자동 정리 210건 적용`.
- "확인", "예/아니요" 대신 결과 동사를 쓴다. 확인 모달의 확정 버튼은 제목의 동사를 반복한다. 취소는 `취소`로 통일한다.
- "~하기"는 `출근하기`, `퇴근하기`에만 쓴다.
- 이동은 끝에 `→`, 새 맥락은 `↗`를 붙인다. 단축키는 라벨 뒤 Kbd로 둔다: `승인 A`, `신청 Ctrl+Enter`.

### 10.4 오류 메시지 공식
**[무엇이 안 됐는지] + [이유(알 때만)] + [다음 행동]**, 한두 문장이다. 사용자를 탓하지 않는다. 코드와 Request-Id는 메타 줄에만 둔다.
| 상황 | 문구 |

- hex 리터럴 금지와 lucide 직접 import 금지는 **lint가 아니라 코드 리뷰 체크리스트**로 확인한다(2명 팀, 커스텀 lint 규칙이 MSW·문자열 `run #…`을 오탐하고 아이콘 사용법과 충돌했다).

- 포커스는 AntD 토큰(`lineWidthFocus`, 컴포넌트별 `colorPrimaryBorder`)과 자체 `:where(...)` 규칙으로 통일한다. box-shadow 링과 `border-radius` 덮어쓰기는 쓰지 않는다.
- `tsc`는 **컴포넌트 토큰** 키 오타만 잡는다. `Table.lineHeight`, `Tooltip.paddingSM`처럼 alias 토큰을 컴포넌트에 덮어쓰는 값은 타입 검사로 보장되지 않으므로 `/dev/kit`의 행 높이 실측으로 확인한다.

### 12.6 1주차 `/dev/kit` 완료 조건
1. statusMap의 배지 전부와 `icons.ts` 아이콘 전부가 렌더된다(`tsc` 통과 포함).
2. 표 1개에서 행·머리 높이가 40±0.5px이다.
3. 시연 PC(없으면 같은 해상도 PC)에서 960px 창 × 80%의 `window.innerWidth`를 실측해 5.4 구간을 확정한다.
