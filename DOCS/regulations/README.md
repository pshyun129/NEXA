# 사내 규정 (주식회사 넥사)

> 이 폴더는 회사 규정의 **원문**이다. 사람이 읽는 기준이면서, ai-service의 규정 검토(RAG)가 근거로 삼는 유일한 출처다.
> 규정 숫자 중 일부는 각 서비스 코드·설정이 실제로 집행한다. **규정과 코드가 다르면 안 되므로, 둘 중 하나를 바꿀 때는 같은 MR에서 함께 바꾼다.**

## 1. 문서 목록

| 파일 | 규정 | 코드 | 소관 |
|---|---|---|---|
| `expense.md` | 경비 및 법인카드 사용 규정 | EXP | 재무팀 |
| `travel.md` | 출장 규정 | TRV | 경영지원팀 |
| `leave.md` | 근무 및 휴가 규정 | LEV | 인사팀 |

## 2. 작성 규칙 (AI가 조항 단위로 정확히 읽기 위한 형식)

- 맨 위 front matter에 `규정명`, `규정코드`, `소관부서`, `시행일`, `개정이력`, `집행`을 적는다.
- 조는 `### 제N조 (제목)`, 항은 `①②③`, 호는 `1. 2. 3.`로 쓴다. 조 번호를 바꾸면 `집행` 표도 함께 고친다.
- 금액은 `30,000원`, 시간은 `오후 10시`처럼 숫자와 단위를 붙여 쓴다.
- 한 조항에는 한 가지 기준만 담는다. (AI가 근거 조항을 정확히 인용할 수 있게)

## 3. 집행 방식

모든 조항은 다섯 가지 중 하나로 분류해 front matter `집행`에 적는다.

| 분류 | 뜻 | AI 규정 검토의 역할 |
|---|---|---|
| **시스템** | 서비스 코드가 이미 강제한다 (막거나 결재선을 정함) | 판정하지 않는다. "시스템에서 자동 적용"으로 안내만 한다 |
| **설정** | 서비스 관리자 설정값으로 집행한다 (휴가 정책 등) | 판정하지 않는다. 설정값이 규정과 같은지는 사람이 확인한다 |
| **AI** | 코드가 강제하지 않는다 (신청 기한, 한도, 증빙, 제한 업종) | **이 조항만 판정한다.** 근거 조항 인용이 필수다 |
| **사람** | 판단이나 운영이 필요하다 (징계, 카드 관리) | 판정하지 않는다 |
| **참고** | 목적, 정의, 시행일 | 다른 조항을 해석할 때만 쓴다 |

> 시스템이 이미 강제하는 규칙을 AI가 다시 판정하면 둘의 결과가 어긋날 수 있다. 그래서 AI는 **코드가 비워 둔 규칙만** 맡는다.

## 4. 규정 ↔ 코드 대응표 (시스템·설정 조항)

| 규정 | 내용 | 집행 위치 | 현재 값 |
|---|---|---|---|
| EXP 제17조 | 경비 정산 전결 기준 | approval-service `app.approval-policy.general-*` | 100만 원 초과 본부장, 1,000만 원 초과 대표이사 |
| TRV 제5조 | 출장 신청 결재 | approval-service `ApprovalPolicy` BUSINESS_TRIP | 국내 팀장, 해외 본부장 |
| LEV 제3조 | 근무·휴게 시간 | attendance-service `work_group` 기본그룹 | 09:00~18:00, 휴게 60분, 주 40시간 |
| LEV 제5조 | 지각·조퇴·누락 기록 | attendance-service `AnomalyType` | 09:00 이후 출근 = 지각 |
| LEV 제6조 | 초과근무 한도·결재·야간 | attendance-service `weekly_max_hours`, 야간 계산 / approval-service `overtime-division-monthly-minutes` | 주 52시간, 월 누적 12시간 초과 본부장, 야간 22~06시 |
| LEV 제8조 | 연차 발생 | leave-service 휴가 정책 (관리자 설정) | 입사일 기준, 1년 미만 월 1일(최대 11일), 1년 이상 15일, 2년마다 +1일(최대 25일) |
| LEV 제9조 | 반차 시간 | attendance-service `LeavePortion` | 오전 09~13, 오후 14~18 |
| LEV 제10조 ④ | 휴가 결재 | approval-service `leave-division-days` | 5일 이상 본부장 |
| LEV 제11조 | 연차 이월 | leave-service 휴가 정책 (관리자 설정) | 최대 5일(2,400분) |
| LEV 제12~14조 | 특별휴가 | leave-service 휴가 유형 (관리자 설정) | 유급·무급, 최대 일수 |

## 5. 개정 절차

1. 규정 원문을 고치는 MR을 올린다. 시스템·설정 조항이면 해당 서비스 설정도 같은 MR에서 바꾼다.
2. 소관 부서(팀원) 리뷰 후 머지한다.
3. ai-service에서 규정 색인을 다시 만들고 평가한다 (`python -m mlops.build_index` → 평가 → 승격 게이트).
4. 색인에는 원문 해시가 기록되므로, 원문만 바뀌고 색인이 옛것이면 바로 알 수 있다.

| 항목 | 내용 | 담당 |

| LEV 제11조 ② | 이월 연차의 사용 기한(다음 연도 6월 30일)을 leave-service `expiry_rule`로 설정할 수 있는지 | 휴가 담당 |
| 휴일근로 가산 | payroll-service는 휴일근로를 시간과 무관하게 1.5배로 계산한다. 근로기준법은 8시간을 넘는 휴일근로에 2배를 정하고 있어 확인이 필요하다 (이 폴더 규정에는 수당률을 적지 않았다) | 급여 담당 |
